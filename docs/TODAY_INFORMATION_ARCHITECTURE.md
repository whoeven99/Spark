## 1. 核心原则

`Today` 不再按“结果桶”组织，而按 **单位模型 + 经营链路 + 维度展开** 组织。

核心原因：

1. `成交结果`、`利润估算`、`ROI` 之间天然存在链路关系，不能视为互不重叠的并列桶
2. 同一指标只能归属于一段经营链路，不能在多个一级模块里重复拥有
3. 页面结构应支持商家按“链路 -> 维度 -> 对象”理解当前经营，而不是浏览一组并列指标目录

因此，`Today` 的基本导航应固定为：

`经营链路节点 -> 主观察维度页 -> 对象决策页`

## 2. 短期经营主链

`Today` 的短期经营只围绕以下四段链路：

1. `流量`
2. `转化`
3. `成交 / 利润`
4. `运营履约`

它们的关系是：

`流量 -> 转化 -> 成交 -> 售后损耗 -> 利润 -> 履约/风控补充`

说明：

- `取消订单`、`退款`、`退货`、`售后损耗` 都归入 `成交 / 利润`
- `发货周期`、`物流周期`、`履约成本`、`风控欺诈` 归入 `运营履约`
- `运营履约` 是保障维度，不和 `流量 / 转化 / 成交利润` 混成同一套分析口径

## 3. 长期价值的定位

`长期价值` 不再作为与短期四段链路并列的第五个一级指标。

新的定位：

- `短期价值`：围绕 `流量 / 转化 / 成交利润 / 运营履约`
- `长期价值`：在更长时间窗口下，重新看上述链路，并额外引入 `客户复购` 维度

因此，长期价值更像：

- 时间维度的切换层
- 或后续独立的客户经营页能力

而不是直接并排塞进 `Today` 首页的另一个短期指标卡。

长期价值相对短期价值新增的关键观察维度：

- `客户复购`
- `新老客结构`
- `高价值客户占比`
- `老客贡献收入 / 利润`

## 4. 单位模型与主维度

### 4.1 流量

- 分析单位：`session / visit`
- 主维度：`渠道`
- 辅维度：`地区`、`落地页`

### 4.2 转化

- 分析单位：`session -> order`
- 主维度：`渠道承接`、`商品承接`
- 辅维度：`地区承接`、`落地页承接`

### 4.3 成交 / 利润

- 分析单位：`order / order_line`
- 主维度：`商品`、`订单`
- 辅维度：`渠道`、`地区`、`售后损耗`

包含：

- 收入
- 订单
- 客单价
- 估算利润
- 估算利润率
- 取消订单
- 退款 / 退货
- 售后损耗

### 4.4 运营履约

- 分析单位：`shipment / fulfillment / risk_event`
- 主维度：`订单`、`物流链路`
- 辅维度：`地区`、`承运商`、`风险类型`

包含：

- 发货周期
- 物流周期
- 履约及时率
- 履约成本
- 风控 / 欺诈异常
- 拒付 / 可疑订单
- 售后处理时效

### 4.5 长期价值

- 分析单位：`customer / cohort`
- 主维度：`客户分层`
- 辅维度：`渠道`、`商品`、`地区`

核心新增：

- 复购率
- 复购周期
- 老客贡献收入 / 利润
- 高价值客户占比

## 5. 一级、二级、对象页结构

### 5.1 一级页

短期一级页固定为：

1. `流量`
2. `转化`
3. `成交 / 利润`
4. `运营履约`

长期维度通过时间范围切换进入，不直接作为短期首页的并列一级页。

### 5.2 二级页

二级页不是“另一个指标页”，而是 **该一级经营节点下的主观察维度页**。

#### 流量

- `渠道`
- `地区`
- `落地页`

默认二级页：`渠道`

#### 转化

- `渠道承接`
- `商品承接`
- `地区承接`

默认二级页：`渠道承接`

#### 成交 / 利润

- `商品`
- `订单`
- `渠道`
- `售后损耗`

默认二级页：`商品`

#### 运营履约

- `发货时效`
- `物流时效`
- `履约成本`
- `风控异常`

默认二级页：`发货时效`

#### 长期价值（时间维度切入后）

- `客户复购`
- `客户价值`
- `新老客结构`

默认二级页：`客户复购`

### 5.3 对象页

对象页作为三级终点页，不再继续开第四层。

统一对象类型：

1. `渠道对象页`
2. `商品对象页`
3. `订单对象页`
4. `地区对象页`
5. `落地页对象页`
6. `客户分层对象页`

统一钻取路径：

`一级页 -> 二级维度页 -> 对象决策页`

## 6. 对象页统一模板

所有对象页统一为五段：

1. `对象结论`
2. `关键指标`
3. `链路表现`
4. `异常 / 机会`
5. `动作建议`

动作类型收敛为：

- `继续放大`
- `优化承接`
- `先止损`
- `继续排查`
- `继续观察`

对象页是决策终点页，不再继续下钻为第四层目录页；如需更深分析，交给 AI 上下文继续延伸。

## 7. 不同对象在链路中的定位

### 7.1 渠道对象页

可跨多个一级页被引用，但解释视角不同：

- 在流量页里：看带来多少 `sessions`
- 在转化页里：看承接强弱
- 在成交 / 利润页里：看带来多少收入与利润
- 在长期维度里：看带来多少复购客户与高价值客户

渠道对象页是最接近全链路的对象页。

### 7.2 商品对象页

重点解释：

- 转化承接
- 成交规模
- 利润贡献
- 退款 / 退货
- 复购带动

商品对象页回答的是：`这个商品到底值不值得继续卖 / 推`

### 7.3 订单对象页

重点解释：

- 订单金额
- 利润
- 取消 / 退款 / 退货
- 发货 / 物流 / 履约
- 风控异常

订单对象页主要用于解释异常样本，不负责整体趋势说明。

### 7.4 地区对象页

重点解释：

- 流量
- 转化
- 成交
- 履约时效

地区对象页更像区域经营面板。

### 7.5 落地页对象页

重点解释：

- 流量承接
- 转化效率

落地页对象页服务流量与转化，不强行承担利润解释。

### 7.6 客户分层对象页

重点解释：

- 复购
- 收入贡献
- 利润贡献
- 留存质量

客户分层对象页主要服务长期价值。

## 8. 指标归属边界

为了避免重叠，后续开发必须遵守以下边界：

1. 没有稳定 `sessions / conversion` 口径时，不把 `流量` 和 `转化` 硬并成“增长质量”
2. 没有完整成本口径时，`成交 / 利润` 中涉及成本的部分必须明确标注为 `估算`
3. `取消订单`、`退款`、`退货`、`售后损耗` 统一归 `成交 / 利润`
4. `发货周期`、`物流周期`、`履约成本`、`风控欺诈` 统一归 `运营履约`
5. `客户复购` 不放入短期四段链路中与其他一级页并列，而作为长期维度的新增观察对象

## 9. 后续开发应优先沉淀的三张定义表

在正式继续改 UI 前，应先补齐以下三张定义表：

1. `经营维度定义表`
   - 定义 `流量 / 转化 / 成交利润 / 运营履约 / 长期价值` 的边界

2. `单位与主维度映射表`
   - 定义每个经营维度的分析单位、主维度、辅维度

3. `指标归属表`
   - 定义收入、订单、利润、退款、退货、发货时效、风控、复购等分别归属到哪里

在这三张定义表稳定之前，页面命名、一级卡片和二级页拆分都不应继续大幅变动。
